## The defect QA caught, and why it mattered

**The first cut shipped `20 of 5 preferred times met`** — `preference-adherence.service.ts:294-295` counted the
denominator in collapsed day-windows and the numerator in stored 15-minute rows. The drill's own T3 ("PREFERRED
mornings only") is 80 stored rows in 5 windows, so one ordinary class per weekday produced `20 of 5`. `R3` passed only
because its fixture was built as seven *single-slot* blocks — an invented fixture shaped around the bug (§11).
Corrected at `f30e338e`: day-window is now the only unit in any ratio, enforced by
`a2-c17-preference-adherence-ratio-invariant` (fails on any ratio > 1), and `R3` re-fixtured from the real picker
surface with `slots.length === 80` asserted so it cannot drift back.

## Judgement calls (open to overrule)

1. **"Times" = painted blocks, not stored rows.** The drill's Step 0 is two blocks and the packet's example line is
   `2 of 2`; row-counting would render `16 of 16`. Detail rows carry no ratio, so one list never mixes units.
2. **A day name appears when a window is one day, dropped when it spans weekdays** — `Unavailable Friday afternoon`
   beside `Prefers mornings`, so five preferred mornings is one line, not five.
3. **Anchored in the workspace body, not the header.** §8 caps a header at two calm rows that row 1 already is, and
   the body strip is the one position automatically correct for both the draft and the published view.
4. **Copies:** group labels always name the day; the singular notice reads `1 teacher has preferences that are not
   reviewed yet, so they were not used.` (the packet's plural has no antecedent for one teacher).
