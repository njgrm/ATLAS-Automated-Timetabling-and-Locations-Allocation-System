## 0. The user, and the standard (AGENTS.md §11 Design judgement gate)

The user is an **older, mouse-first school scheduler** who wants one obvious next step and
is not reading English error vocabulary. Every item below is judged against four questions,
and **a miss on any one of them is `REJECT_UX` even when every test passes**:

1. **One primary action.** Is there exactly one thing to do next on this screen?
2. **No truncation, nothing cramped.** At 1366×768 nothing is cut, ellipsised or squeezed
   into a second meaning. At 390px a row wraps instead of truncating.
3. **No jargon, no raw codes.** No `TERM_CACHE_INVALID`, no `OWNER_DEPT`, no
   `PENDING_DERIVED_DEMAND_INTEGRATION`. A code belongs behind `Help`/`Details`, never in
   the visible label.
4. **One status per fact, and controls that match other pages** (§8 "One look per control").

**Subtract first (§11 rule 3).** No item below may add a visible word, chip, line or control
to a region without removing at least as much. Where this packet says "one panel", it means
*one* panel — the loading state you add must cost the screen fewer things than it has now.

**Design before code.** Write a short layout note in your handoff: what stays, what goes,
what moves behind `Help`/`More`, per item, before you write JSX. Check it against §8 and
against the page that already does this well — `/subjects`' own `SubjectTermContractPopover`
(the quiet footer affordance) and `@/ui/filter-picker`.

## 1. `TERM_CACHE_INVALID` is read to the operator; the code is the visible label

**Finding (Lane C, verbatim):** "Show `TERM_CACHE_INVALID` as *Term information needs
updating before scheduling*, and put the code behind Help."

**What is true today** (`atlas-client/src/components/subjects/`):
- `subject-source-utils.ts:48-93` already maps `TERM_CACHE_INVALID` to calm
  description/next-action copy. That copy is correct and **stays**.
- `SubjectTermAuthorityBanner.tsx:97-101` renders the **raw code as the popover's visible
  trigger label**, in `font-mono text-[0.65rem]`. That is the defect: the operator's screen
  reads `TERM_CACHE_INVALID` where a verb should be.
- `SubjectTermAuthorityBanner.tsx:72-78` derives the banner **headline** from `state` alone,
  so `TERM_CACHE_INVALID` (a `VERIFIED_CACHED` state) inherits the stale-source headline
  "Using saved EnrollPro year and terms" — which does not tell the scheduler that the *term*
  information is the thing that must be updated before they can schedule.

**Do exactly this:**
1. The diagnostic trigger's **visible label is plain words** — `Help` — with the existing
   `Info` icon. The raw `code` moves inside the popover only. Keep the existing
   `aria-label` (it already carries the code for assistive tech) and keep
   `data-testid="subject-term-authority-detail"`. **No `font-mono` code in any visible
   label on this page.**
2. The headline becomes **code-aware**. Add a `headline` to the `TERM_AUTHORITY_COPY` map in
   `subject-source-utils.ts` — or a sibling resolver in that same file, your call, but the
   headline must be resolved from the **code**, not from `state` alone. For
   `TERM_CACHE_INVALID` it is the operator's own sentence: **"Term information needs
   updating before scheduling."** Every other mapped code keeps the current state-derived
   headline unless it has a code-specific one; the fallback for an unmapped code is today's
   headline, unchanged.
3. `resolveTermAuthorityCopy` is the single place that decides the words. It grows a
   `headline` field; **the existing `description` and `nextAction` strings do not change** —
   `a3-c4-subjects-copy.test.tsx` pins them and they are the current, accepted copy.

**Failing-first, before you change the source** (record the base failure and its literal
output in the handoff):
- A rendered test mounts `SubjectTermAuthorityBanner` with
  `termAuthority = { state: 'VERIFIED_CACHED', code: 'TERM_CACHE_INVALID', message: '…' }`
  and asserts the **trigger's text content** does not contain `TERM_CACHE_INVALID`, that it
  reads `Help`, and that the headline reads *Term information needs updating before
  scheduling*. On the base this fails twice.
- A second assertion opens the real popover (real `pointerdown`, as the c3 slice did) and
  asserts the code and the raw server message are **still both there** behind it. This is
  the anti-deletion control: the evidence moves, it is not destroyed.
- Every **existing** pin in `a3-c4-subjects-copy.test.tsx` (3a, 3b, 3b2) must still pass
  untouched. Do not edit that file. If a pin breaks, you changed behaviour you were not
  asked to change — re-read and revert that part.

## 2. `/subjects` filters: Grade and Program stay visible; the rest go under "More filters"

**Finding (Lane C, verbatim):** "Keep Grade and Program visible and put the other filters
under 'More filters'."

**The screen today** (`SubjectFilterToolbar.tsx`): one row —
`Search | Status | Grade | Program | Room | Term | Reset`, five `FilterPicker`s, each
`w-32`/128px. It holds one line at 1366px, and Codex confirmed no truncation on this page.
**This item is not about a width problem. It is about five competing controls where the
scheduler has to read all five to know the page is filtered.** Grade and Program are what a
scheduler filters by; Status, Room and Term are refinements.

**Do exactly this:**
- Visible in the row: **search, `Grade`, `Program`**, and (only when a filter is set) the
  existing `Reset`.
- Under **one** disclosure labelled **`More filters`**: `Status`, `Room`, `Term`.
  - It is a `@/ui` primitive (`Popover` or `DropdownMenu` — whichever this repo's
    `@/ui` already exports and uses for a filter group; do not hand-roll).
  - Its label **names the state**: `More filters` when nothing is set, and
    `More filters (2)` when two of the three are set, so a hidden active filter is never
    invisible. The count is of *set* filters, never of options.
  - Each picker inside it keeps **its own** self-naming trigger (`Status: All`,
    `Room: All`, `Term: All` — the short form the c3 slice established) and **its own**
    `data-testid`. The three existing testids must keep resolving:
    `subjects-status-filter`, `subjects-room-type-filter`, and the term picker's.
  - The group is **keyboard reachable and closes on `Escape`/outside click**, and **Enter
    cannot select a `disabled` option** (c3 slice B's B1 regression — do not reintroduce it).
  - It is a *disclosure*, not a second value: opening it must not silently change any
    filter, and it must never claim `All` for a control that offers no such choice
    (c3 slice B's B2 regression).
- `AdminSearchFilterToolbar` already takes `filtersOpen` / `onToggleFilters` /
  `primaryFilterCount` / `primaryFilterLayout`, and this page currently passes
  `filtersOpen={false}` and `onToggleFilters={() => {}}` — dead props. Wire the real values
  to the disclosure. If, after wiring, the `false`/`no-op` is dead in the shared component,
  say so in the handoff and leave the shared component alone (it is other lanes' file).
- **A sentence cut off with an ellipsis is a defect**, including in a picker option. Long
  option labels (`Science Laboratory`) are fine in the option list; a truncated *trigger
  label* is not.

**Failing-first:** a rendered test that mounts the toolbar with all filters at their
defaults and asserts (a) `Grade` and `Program` triggers are visible without any interaction,
(b) `Status`/`Room`/`Term` are **not** in the visible row, (c) after opening the disclosure,
all three are present and individually operable, (d) with `Room = 'LABORATORY'` set, the
disclosure reads `More filters (1)` and the trigger still reads `Room: Laboratory`, and (e)
`Reset` appears and clears all five when any filter is set. On the base, (b) and (d) fail.

## 3. Never an empty table under "Checking source" — one calm progress panel

**Finding (Lane C, verbatim):** "Never show an empty table under 'Checking source'. Show one
progress panel until rows are ready." (Codex run 2, MAJOR: "an empty table under 'Checking
source' invites guessing".)

**What is true today** (`pages/Subjects.tsx:543-551, 670-747`): `subjectSourceState` is
`'checking-source'` while `!actorScopeResolved || loading`. The page renders the table
shell regardless, filling `tbody` with **8 skeleton rows** while `loading` and an
`AdminStatePanel` empty state when `paged.length === 0`. So the source chip can read
**Checking source** above a table that shows zero rows and no explanation of which of the
two things is happening — that is the "invites guessing" the walk saw.

**Do exactly this:**
- While the first catalog response has not resolved (`loading`, or the actor scope is
  unresolved) render **one** centred progress panel in place of the table shell, with **one**
  calm sentence naming what is happening and the page it belongs to (e.g. *Loading
  subjects…*). It replaces the skeleton grid — **that is the subtraction**; do not add the
  panel *and* keep eight skeleton rows. Use the `AdminStatePanel` shape the page already
  uses at line 657 so it is the same component, not a new one.
- The **source chip and the body must never disagree**: an empty table must never render
  while the chip says `Checking source`, and the chip must leave `checking-source` as soon
  as the first response has resolved — including a resolved-empty one.
- **Unchanged, and named as unchanged:** the `actorScopeResolved && actorSchoolId == null`
  "School scope unavailable." panel with its `Retry`; the post-resolution empty state
  ("No subjects found." / "No matches found."); the footer pagination; the mobile list; the
  error banner and its retry. A slow load that eventually resolves with rows must show the
  rows, not the panel forever — the panel is bounded by the first response, not by a timer.
- If a **time limit** is genuinely needed to stop a hung load being indefinite, it must be
  the existing error+retry path (a real error, one `Retry` button), **not** a new timer or
  a new chip. Do not invent one; A8 owns the stall.

**Failing-first:** a rendered `Subjects` test (mock `/api/v1`, real component) that holds the
catalog request pending and asserts (a) exactly one progress panel is present, (b) **no
`<table>` and no skeleton row is rendered**, and (c) the `Checking source` chip is present
only while that panel is. Then resolve the request with rows and assert the table replaced
the panel; resolve it empty and assert the chip has left `Checking source` and the empty
state is the honest one. On the base, (b) fails and (c) is satisfiable only by accident.

## 4. Shell: a route change must never leave the old page's content on screen

**Finding (Lane C, verbatim):** "when you change page, the old page's content stays up (for
example, /teachers showed Sections). Show that page's own loading state."
(Codex run 2, MAJOR, route changes.)

**The cause, read before you change anything.** `atlas-client/src/components/AppShell.tsx:576-589`:

```
<AnimatePresence mode="wait">
  <motion.div key={resolveOutletKey(location.pathname, routeEpoch)} … exit={{ opacity: 0 }} …>
    <Suspense fallback={suspenseFallback}>
      {outlet && React.cloneElement(outlet, { key: resolveOutletKey(...) })}
```

`mode="wait"` means the **new** route is not rendered until the **old** one has finished
exiting. The old page therefore stays mounted and visible under the new URL for the whole
exit window, and that window is not bounded in practice: the exit completes on an animation
frame, so a throttled or blocked main thread (exactly what the A8 stalls and the leaked
streams cause) can leave the previous page on screen indefinitely. On top of that the
fallback is `<Skeleton className="h-100 w-full" />` — one grey bar, which is not a loading
state a scheduler can read.

**Do exactly this:**
- The new route's own loading state appears **at once**. Remove the `mode="wait"` gate
  (and the `AnimatePresence` wrapper if nothing else needs it); keep the `key` on the
  outlet — it is what gives a route change a clean remount and it is depended on
  (`resolveOutletKey` is exported and pinned by tests).
- The `Suspense` fallback becomes **a calm, page-shaped loading panel**: the shared
  `AdminStatePanel` shape (or the existing `TimetableSkeleton` for `/timetable`, which
  already works) with **one** sentence naming the page being opened. Derive the page name
  from `resolveRouteChrome(location.pathname)`, which `AppShell` already calls at line 448 —
  do not invent a second title source. **No `h-100` bar, no generic spinner with no words.**
- **Nothing else in `AppShell` changes**: the sidebar, the auth bridge, `routeEpoch`,
  `resolveOutletKey`'s signature and value, the school-year switcher, and every gate in
  this 595-line file are out of scope. If you find yourself editing them, stop and re-read.
- Prefer **extracting** the outlet + fallback into `components/app-shell/RouteOutlet.tsx`
  so it is renderable in a test without the whole authenticated shell. That extraction is
  the point of the item: it is the testable seam, and it also keeps `AppShell.tsx` under
  the §8 cap.

**Failing-first:** a rendered test on the extracted `RouteOutlet` (or, failing extraction, on
`AppShell` with its auth calls stubbed) that renders route A, then swaps the outlet to a
route B **whose module never resolves** (a `lazy` that never settles), and asserts:
(a) route A's distinctive content is **absent from the document** at the moment B is
requested — this is the row that fails on the base, and it must fail on the base with
`AnimatePresence`'s wait behaviour visible; (b) B's loading panel, naming B, is present;
(c) route A's content never reappears. Add the negative control: when B's module *does*
resolve, B's content renders and the panel is gone.
