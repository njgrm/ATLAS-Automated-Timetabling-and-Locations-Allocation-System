## Defect (reproduced on a read-only restore of live, 2026-09-30 00:58 +08)

Live year 5 (2026-2027, `schoolYearId` 5) read through the real `buildGenerationReadiness(1, 5)`:
`status READY`, `generateAllowed: true`, `blockerCount 0`, `gapCount 64` (**4 classes**), `advisoryCount 0`,
`zeroWrite: true`, scheduler 900 assigned / 20 unassigned / 920 classes. The operator pressed Generate on live and got
`409 GENERATION_PREFLIGHT_BLOCKED` ("Generation is blocked by its read-only preflight…", `generation.service.ts:849`).

Cause: the same rows are pushed into `preflight.blockers`, and
`atlas-server/src/services/generation-preflight.service.ts` returns `ok: sortedBlockers.length === 0` (~line 1340),
so ANY row — including the ADVISORY / COVERAGE-GAP rows readiness already classifies as non-blocking — fails the
trigger. The advisory classification already exists in exactly one place,
`generation-blocker-groups.service.ts` (`classifyGenerationBlockers`, `deriveGenerateDecision`, `ADVISORY_CODES`,
`COVERAGE_GAP_CODES`); readiness consumes it, the trigger does not.

## The one fix — one source for the gate

In `atlas-server/src/services/generation-preflight.service.ts`, derive `ok` from the shared classification instead of
the raw row count:

```ts
const classification = classifyGenerationBlockers(sortedBlockers);
// ...
ok: classification.blocking.length === 0,
```

Import `classifyGenerationBlockers` from `./generation-blocker-groups.service.js` (that module's own import of the
blocker type is `import type`, so there is no runtime import cycle).

Constraints — do not exceed this:

- Change **no code set**: `ADVISORY_CODES`, `COVERAGE_GAP_CODES`, `ATTRIBUTABLE_GAP_CODES`, `deriveGenerateDecision`,
  `resolveUnassignedViolationCode`, and every publication predicate stay byte-identical.
- `blockers` must still be returned **COMPLETE** — readiness classifies that array and the panel lists it. Do not
  filter, reorder or drop rows.
- Every non-advisory, non-coverage code must still fail the trigger —
  `POLICY_UNINITIALIZED`, `TERM_AUTHORITY_UNRESOLVED`, `INACTIVE_HISTORICAL_YEAR`, `SECTION_SETUP_REQUIRED`,
  `TEACHING_LOAD_REVIEW_REQUIRED`, `CANONICAL_SHAPE_CAPACITY_EXCEEDED`, `SEARCH_LIMIT_UNRESOLVED`, every `FLAG_*`,
  every `ROOM_*`, `TL_OWNERSHIP_CONFLICT`, … are BLOCKING and must keep `ok: false`.
- Do not change the trigger's error code, message, `actionHint`, or `details` shape in `generation.service.ts`; the
  fix is the single `ok` source. If you find a **second** place that computes the gate from the raw row count, report
  it in the handoff and leave it alone (planner decides).
- The gaps stay visible: those classes are left unassigned in the draft and listed by the existing run result — prove
  it in A4, do not add new listing code.
