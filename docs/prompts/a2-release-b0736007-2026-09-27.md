  wrong and is corrected here. **Pin the method, not the numeral** — the numeral is what a later reader will
  quote, and two reviewers and an executor have now disagreed on it.
- **D7b — live signature before/after, with a falsifiable attribution rule.** Rev 2's rule could be passed by
  assertion, because it never pinned *which* actors are authorised, never bounded the window, and treated a
  decrease as attributable. All four clauses are now mandatory:
  1. **Pinned authorised-actor set.** `authorisedActorIds = { 46 }`. **Provenance:** `46` is the
     operator/QA acting actor established by the prior recorded runs on this deployment (the term-cache
     catch-up capture's login audit 793, actor 46, and the 2026-09-12 deploy acceptance whose exact approved
     login delta was `LOCAL_LOGIN_SUCCESS` actor 46). **Record the set literally before cutover.** If the Lane C
     freeze is refused and Lane C reports a different acting actor, **add it to the set explicitly here before
     proceeding** — never widen it silently mid-window. Every attributable delta's `audit_logs.actor_id` must be
     in the pinned set. *(A wider default would be less safe, not more: it would let the check pass for an
     unidentified actor, which is the pass-by-assertion hole this rule exists to close.)*
  2. **Literal window stamps.** Record `windowStart` and `windowEnd` as literal UTC ISO-8601 instants bracketing
     the cutover. A delta row counts as in-window only if its `created_at` is **between them inclusive**.
  3. **`actor_id IS NULL` fallback.** A system- or scheduler-originated row can carry no `actor_id`. Such a row
     is **attributable only if** its `audit_logs` action and target identify the supervisor/scheduler; otherwise
     it is unattributable → BLOCKING. Stated so a legitimate system write is not a false failure and a real one
     is not waved through. **Note: currently dead text** — `audit_logs.actor_id` is `NOT NULL`
     (`prisma/migrations/0000_clean_baseline/migration.sql:605`). Harmless, and it becomes correct if the column
     is ever relaxed; **do not rely on it as a live path.**
  4. **Direction rule.** **Any decrease in any table is BLOCKING, always.** A deletion is never an authorised
     publish. Only increases may be attributed.

  Capture row counts for `generation_runs`, `manual_schedule_edits`, `audit_logs`,
  `published_schedule_revisions`. An **unattributable** increase inside the window is **BLOCKING**. A
