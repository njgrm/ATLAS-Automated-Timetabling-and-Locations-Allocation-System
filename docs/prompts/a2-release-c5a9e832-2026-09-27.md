## 7. Operational facts

- **`cli.mjs status` reports `"live": false` structurally.** `status.mjs:27` ← `supervisor.mjs:401`, where `live`
  derives from an in-memory map populated only in the spawning process, so a non-owning `status` call is
  **structurally always false**. **Do not read a deploy failure out of it.** The state file's
  `state`/`ownedPids`/`releaseSha` **must still be trusted** — and only the `supervisor-state.json` inside the
  **active** `ATLAS_RUNTIME_SOURCE_DIR` is authoritative.
- `EADDRINUSE` on 5001 during cutover is **expected**, not a defect.
- An out-of-process `cli.mjs stop` does **not** quiesce the resident supervisor. **End the scheduled task first** —
  on the previous A2 cutover that alone quiesced the whole tree cleanly, with no manual kill needed.
- A stale state file makes `start` fail with `ALREADY_RUNNING`; clear it if so.
- Pass explicit `ATLAS_RUNTIME_SOURCE_DIR`/`ATLAS_RUNTIME_RELEASE_SHA` into every `cli.mjs` call. Read identity from
  **machine scope** + the task action + the listeners, **never from `Env:`** — a stale process-scope pair has
  caused a real false alarm here.
- Re-point the task by exporting its XML, replacing the release path **in both occurrences** (`<Arguments>` and
  `<WorkingDirectory>`), and re-registering. **CORRECTION (F3/F4):** the exported form is **UTF-16LE with a BOM**
  (measured: 3012 bytes, first four `FF FE 3C 00`, exactly 2 non-ASCII bytes — the BOM — and a literal
  `<?xml version="1.0" encoding="UTF-16"?>`). Only its *characters* are ASCII, so "ASCII bytes" was the wrong
  description and would invite a well-meaning "fix". The rewrite must therefore be **UTF-16LE-aware**: decode,
  replace both occurrences, re-encode as UTF-16LE **with** the BOM, and do **not** touch the declaration. Measured
  on this host, it registers cleanly that way and rewriting the declaration to UTF-8 fails.
- **`schtasks /change /tr` fails** on this host with a path containing spaces — use the XML route. *(Not
  independently re-verified read-only, because the only faithful test risks mutating the real task; it is bypassed
  either way because the XML route is mandated.)*
- `productPin`/`releaseLabel` in the state file is the ancestor-milestone floor, **not** live identity.
