## 1. Item 2 (FIRST) — Swap with another class: swap at once, never hang

**Observed by Codex:** "Swap with another class shows *Review swap before saving* and then sticks on
*Checking swap options.* with the *Swap sessions* button disabled."

**Where it is (verify, do not trust this list blindly):**
- Arm: `ScheduleReviewWorkspace.tsx` `armSwapSessions` (≈`:209`) → `createSwapArmHandler`
  (`components/timetable/timetableSwapArming.ts`), then first pick / second pick in
  `useScheduleReviewWorkspaceState.ts` (≈`:1169–1218`).
- Second pick → `openRegularSwapPrompt` (`useTimetableMutations.ts:1567`) → `POST
  ${apiBase}/swap/preview` where `apiBase = /generation/{schoolId}/{schoolYearId}/runs/{runId}/manual-edits`
  (`useTimetableMutations.ts:1048`). **There is no request timeout** — a request that never settles
  leaves `regularSwapPreview.loading = true` forever.
- Dialog: `modals/TimetablePlacementDialogs.tsx` — status text `Checking swap options.` (`:830`) and
  the commit button `disabled={regularSwapSaving || !regularSwapStrategy || committedSwapMove === null}`
  (`:848`). Commit body: `executeRegularSwap` (`useTimetableMutations.ts:2051`) → `POST ${apiBase}/swap`.
- The strip sentence `Review swap before saving. This occupied slot will exchange the two sessions.`
  is set at `useScheduleReviewWorkspaceState.ts:1964` and `:2112`.

**Required outcome (all four):**
1. **One action.** When the operator picks the second class, the swap is applied. No review dialog
   stands between the pick and the save. The operator must never have to find and press a second
   button to make their own swap happen.
2. **Never hang.** The UI resolves to a decided state within a bounded wait (name the number in the
   code and in your handoff; a few seconds, not minutes). No path may leave a spinner or a disabled
   button standing indefinitely. On timeout or a refused commit, say in plain words what happened.
3. **Receipt.** The committed swap shows the ONE existing receipt — `buildEditReceipt` /
   `timetable-edit-receipt.ts`, the same module move and place already use (`executeRegularSwap`
   ≈`:2098` already composes it). One committed change gets one sentence; do not add a second.
4. **Undo.** The swap must register the contextual Undo the other committed changes register
   (`lastAutoSaveUndo`, ledger `run`, with the commit result's edit id) — **`executeRegularSwap` does
   not do this today**. Undo must actually revert the swap.

**Do not delete the auto-fix capability to make this easy.** The server still owns
`DIRECT_SWAP` / `AUTO_FIX_MOVE_BLOCKING` / `AUTO_FIX_MOVE_SOURCE` (`manual-edit.service.ts`,
`previewManualSwapEntries` / `swapManualEntries`). If your one-action design no longer surfaces the
auto-fix strategies in a dialog, then when a direct swap is refused you must still offer the operator
a way forward (the nearest free slot — item 4's machinery), and you must **state in the design note**
that the dialog was removed and where the capability went. If an existing test asserts the removed
dialog, supersede it **in place** — keep the original assertion and add your replacement beside it
(AGENTS.md §16) — and say so in the handoff.

**Failing-first control (item 2):** two assertions, both of which must fail on `607f2363`:
- (a) *one action + receipt + Undo*: with a legal pair, the second pick performs the commit and
  renders the receipt sentence and the Undo affordance, without any dialog commit button in the path.
- (b) *never hang*: with the preview/commit request never resolving, the surface resolves within the
  bound to plain words — it is **not** left on `Checking swap options.` and the commit control is not
  left disabled forever. Use a never-resolving promise plus fake timers.
